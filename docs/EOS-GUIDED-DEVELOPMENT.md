# EasyOpticSim Y1.2 引导设计与验证助手

Y1.2 将 Ayr1k 通过 PR #1 贡献的引导式 EOS 工作流正式纳入 EasyOpticSim。它减少默认入口，但继续使用同一套 Rust 光学模型、候选机制和专业工具；“容易使用”不意味着降低验证标准。

## 使用新流程

1. 选择「引导设计」，工作区只保留「我的目标」「画面与改进」「检查与保存」三个主入口。
2. 新建项目依次选择用途、画幅和拍摄距离，设置目标，确认模板限制，执行基础检查，再创建。未检查或未达标的起点明确标为实验草稿。
3. 「我的目标」区分目标与当前焦距、光圈；更多条件可展开精确设置。
4. 「画面与改进」展示逐视场光点 RMS、采样、画幅、距离与波长。
5. 选择全画面、中心或边缘优先，点击「检查并尝试改进」。助手先诊断结构与通光，再尝试对焦和受约束优化。
6. 通过复核后查看前后差异及修改的参数，点击「查看候选与采纳条件」，最后在候选卡片中确认采纳。所有采纳均可撤销。
7. 运行完整体检并保存 `.eos.json`。缺失检查、目标未满足、覆盖不足或衍射未收敛都会保留说明。

「更多工具」保留镜片编辑、结构检查、光点分布、测试图成像、精细画质、对焦与光圈扫描、版本和图纸。「高级工作区」保留完整参数控制。

## 自动化与精确性

- 模板使用稳定 ID 与明确文件绑定，保留真实材料、波谱和已有结构限制。
- 新项目清除模板的旧版本和旧优化变量，再记录用户选择的画幅、距离、焦距、F 数和尺寸目标。
- 默认助手最多选择五个非光阑曲面的曲率和最后像距；已有变量表、锁定和边界继续生效。
- 显式配置未开放像距时，跳过自动对焦与阶段间重对焦；最终再次核对所有锁定和边界。
- 助手不自动修改材料、画幅、波长、口径或目标，也不会放宽已有约束。
- 对焦只能作为通过引擎约束的中间起点；优化失败时仍可独立复核对焦候选。
- 原始处方与候选都用 65×65 几何采样比较。逐视场不允许退步，不能通过增加遮挡获得更小的 RMS。
- 候选重新检查设计约束、连续结构和画质底线；传感器模式下，覆盖缺失或失败会阻止采纳。
- 候选所有画面位置执行最高 128 瞳采样的衍射检查，并要求引擎报告收敛。
- 取消计算、改变项目或退出页面后不会回填旧结果。

改善指标是几何光点 RMS，不意味着所有空间频率的 MTF 改善。有限采样和收敛判据不是制造、公差、镀膜、杂散光、机械强度或真实相机认证。Y1.2 没有新增全局搜索、自动选玻璃或自动生成镜头结构；没有可验证的改进时，助手会明确停止并保留原设计。

## 本地验证

```powershell
pnpm install --frozen-lockfile
cargo build -p easyopticsim-cli --locked
pnpm test
pnpm build
cargo test --workspace --locked --release
cargo clippy --workspace --all-targets --locked -- -D warnings
```

真实引擎集成测试需要先构建 debug CLI，再设置环境变量：

```powershell
cargo build -p easyopticsim-cli --locked
$env:EOS_ENGINE_TEST = '1'
pnpm test
```

该测试会将长焦示例像面移开 2 mm，要求助手通过真实 Rust 引擎恢复有效候选，并完成独立几何与衍射复核。默认测试会跳过这一项，以免要求所有前端开发环境安装 Rust。
